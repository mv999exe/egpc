# الشرح التقني — المشروع اتبنى إزاي وليه

مستند تقني تفهم منه المعمارية، آلية الضغط، سبب اختيار كل تقنية/مكتبة،
والإمكانيات اللي في إيدنا. (عربي + مصطلحات إنجليزي)

> **تحديث مهم (النسخة 2.0):** المشروع اتحوّل من ضغط **داخل المتصفح (client-side)**
> إلى ضغط **على السيرفر (server-side)** باستخدام `sharp` (libvips) وصيغة **AVIF**.
> السبب: ده أقوى ضغط ممكن للمستندات والنصوص — أصغر حجم مع بقاء النص واضح للقراءة،
> وده اللي كان مذكور في القسم القديم إنه "أفضل بس محتاج سيرفر". القسم ده اتنفّذ دلوقتي.

## اسم التقنية (خلاصة سريعة تشرحها للناس)

| الطبقة | التقنية / الاسم |
|---|---|
| **محرّك الضغط** | `sharp` (فوق **libvips**) + مشفّر **aom** — يشتغل على السيرفر |
| **صيغة الإخراج** | **AVIF** = **AV1 intra-frame coding** |
| **الإعدادات** | AVIF quality 60 · `effort: 9` · `4:4:4` · سقف **1600px** · **وضع مستند تلقائي** |
| **السيرفر** | **Node.js** + **Express**، ورفع الملفات بـ **Multer** (في الذاكرة) |
| **الواجهة** | HTML/CSS/JavaScript عادي (Vanilla)، سلايدر before/after يدوي |
| **الأمان** | **HTTP Basic Auth** (كلمة مرور) + ربط **loopback** + **Cloudflare Tunnel** |

الجملة الجاهزة للشرح: *"بنضغط الصور على سيرفر Node بمكتبة sharp (libvips) ونطلّعها
AVIF بإعدادات مظبوطة للمستندات، والوصول من بره البيت بيتعمل عبر Cloudflare Tunnel
مع كلمة مرور على التطبيق — من غير ما نفتح أي منفذ على الراوتر."*

## 1) نظرة عامة على المعمارية

المشروع بقى **تطبيق Node.js**: سيرفر خفيف (Express) بيقدّم صفحات ثابتة +
**API واحد للضغط** بيشتغل بمحرّك `sharp`.

```
egpc/
├── server.js             # سيرفر Express + API الضغط (sharp → AVIF)  ← المهم
├── package.json          # الاعتماديات: express, multer, sharp
├── public/               # الواجهة (static)
│   ├── index.html        # الصفحة الرئيسية (8 كروت)
│   ├── compressor.html   # صفحة ضغط الصور
│   ├── css/styles.css    # ثيم أبيض/أسود
│   └── js/
│       ├── home.js       # منطق كروت "Coming soon"
│       └── compressor.js # يرفع الصورة للـ API ويعرض before/after
└── docs/                 # المستندات
```

**ليه اتحوّلنا لـ server-side؟**
- **جودة/حجم أعلى:** المُرمِّز بقى `libvips + aom` (AVIF) بـ **`effort: 9`** (أقصى بحث)
  — مش محدودين بمُرمِّز المتصفح زي قبل. ده بيدّي أصغر حجم لنفس الجودة.
- **صيغة AVIF:** كانت مستبعدة قبل كده لأن `canvas.toBlob('image/avif')` مش مدعوم
  بشكل موثوق في المتصفح. على السيرفر مفيش القيد ده → نستخدم أقوى صيغة.
- **ثبات:** نفس النتيجة على أي جهاز، مستقلة عن إمكانيات موبايل المستخدم.

**ليه Express + Vanilla JS من غير framework؟** المشروع صغير — إضافة React/بيلد
هتبقى over-engineering. الكود قليل ومباشر وسهل الصيانة.

## 2) آلية الضغط — الأساسيات (الأهم)

### أ) المسار الكامل
1. الواجهة (`public/js/compressor.js`) بتاخد ملف الصورة وتبعته `POST /api/compress`
   كـ `multipart/form-data`.
2. السيرفر بيستقبله في الذاكرة (`multer` memoryStorage)، ويمرّره على `sharp`.
3. `sharp` بيعمل: تصحيح دوران EXIF → تصغير للأبعاد المسموحة → ترميز AVIF.
4. السيرفر بيرجّع بايتات الصورة المضغوطة + الحجم/الصيغة في response headers.
5. الواجهة بتعرض النتيجة في سلايدر before/after وبتحسب نسبة التوفير.

### ب) الإعدادات اللي اخترناها (في `server.js`) وليه
```js
const MAX_DIMENSION = 1600;          // سقف أطول ضلع (أكبر رافعة للحجم)
const AVIF_QUALITY  = 60;            // جودة AVIF (1–100)
const AVIF_OPTS = { effort: 9, chromaSubsampling: "4:4:4" };
const CHROMA_THRESHOLD = 18;         // تحت كده = مستند (شبه رمادي)

// لو مستند: نشيل اللون ونسطّح الخلفية ونشحذ النص قبل الترميز
let img = sharp(input, { failOn: "none" }).rotate()
  .resize({ width: 1600, height: 1600, fit: "inside", withoutEnlargement: true });
if (doc) img = img.grayscale().normalise().sharpen({ sigma: 0.6 });
img.avif({ quality: 60, effort: 9, chromaSubsampling: "4:4:4" });
```

**الروافع المضبوطة:**
1. **`MAX_DIMENSION = 1600` (الأبعاد — أهم رافعة):** الحجم بيتحكم فيه **عدد البكسلات**
   قبل أي حاجة. ده سرّ إن الـ screenshot أصغر من الأصل — دقة أقل مش ضغط أحسن. 1600px
   بيخلي المستند وأصغر خط **مقروء على الشاشة/الموبايل** بأصغر حجم. `withoutEnlargement`
   يمنع تكبير الصور الصغيرة. (قابل للتغيير بـ `MAX_DIMENSION`.)
2. **وضع المستند التلقائي (`isDocument`):** بنقيس «الألوانية» (متوسط `max-min` للـ RGB)
   على صورة مصغّرة 64px. لو أقل من `CHROMA_THRESHOLD` → مستند: **رمادي** (نشيل قنوات
   اللون اللي بتاكل بايتات ببلاش) + **`normalise`** (نسطّح خلفية الورقة ونشيل زغللة
   المسح → أصغر **وأوضح**) + **شحذ خفيف** للحواف. الصور الملوّنة بتفضل بألوانها.
3. **`quality: 60`:** توازن للنصوص — حواف نظيفة عند حجم صغير. (محاولة تانية بجودة 46
   بس لو 60 مطلعش أصغر من الأصل.)
4. **`chromaSubsampling: "4:4:4"`:** للصور الملوّنة، بيمنع تلطيخ اللون على حواف النص
   (الافتراضي 4:2:0 بيلطّخها). في وضع المستند مش مهم لأننا رمادي أصلاً.
5. **`effort: 9`:** أقصى مجهود بحث في مُرمِّز aom → أصغر حجم لنفس الجودة.

### ج) الضمانات اللي أضفناها
- **مستحيل الناتج يكبر عن الأصل:** بنقارن حجم AVIF بحجم الأصل؛ لو مطلعش أصغر
  حتى بعد محاولة جودة أقل، بنرجّع **الأصل نفسه** ونعلّم `X-Kept-Original: 1`.
- **تجريد الـ metadata (EXIF):** افتراضي في `sharp` → خصوصية + حجم أقل.
- **حد أقصى للرفع 40MB** (`multer` limits) لحماية السيرفر.

**نتيجة نموذجية (بعد سقف 1600 + وضع مستند):** مستند أبيض/أسود بينزل لـ **~90% أصغر**
(مثال قِسناه: 70KB → 7KB)، وصورة ملوّنة بتفضل بألوانها وتنزل **~75%**. الاتنين من غير
أي فقد ملحوظ في التفاصيل المقروءة (اتأكدنا بصريًا من قصاصات نص قبل/بعد وعند دقات مختلفة).

## 3) ليه صيغة AVIF؟ (وليه مش WebP/JPEG)

| الصيغة | الحجم | جودة النص/الحواف | القرار |
|---|---|---|---|
| **JPEG** | مرجع | حواف النص بتتلطّخ (DCT + 4:2:0) | ❌ |
| **WebP** | أصغر 25–35% من JPEG | كويس بس أقل من AVIF على النص | احتياطي نظري |
| **AVIF** | أصغر 20–50% من WebP | **الأفضل للنص** (AV1 intra + 4:4:4) | ✅ **المختار** |
| **PNG** | كبير (lossless) | مثالي بس حجمه ضخم | مش مناسب |

**تقنيًا:** AVIF مبني على **AV1 intra-frame coding** — تنبؤ اتجاهي أدق، تحويلات
أكبر وأمرن، وترميز حسابي أكفأ من DCT+Huffman بتاع JPEG أو VP8 بتاع WebP. على النص
والخطوط ده بيدّي حواف أنضف عند bitrate أقل. مع `4:4:4` بنشيل عيب تلطيخ اللون.

**التوافق كملف منزّل:** AVIF بيتفتح على كل المتصفحات الحديثة (Chrome/Edge/Firefox/
Safari 16+) وويندوز/أندرويد/iOS الحديثة. ده كان القيد الوحيد قبل كده — ومقبول دلوقتي
لأننا اخترنا "أفضل تقنية ممكنة" زي المطلوب.

## 4) ليه `sharp` (libvips)؟ وليه مش غيره

| الخيار | المميزات | ليه أخدناه/سبناه |
|---|---|---|
| **sharp / libvips** ✅ | سريع جدًا (streaming, multi-core)، AVIF/WebP/JPEG، aom مدمج، prebuilt binaries | **الأنسب**: أقوى جودة/حجم بأقل تعقيد |
| Pillow (Python) | ناضج | يحتاج stack بايثون منفصل؛ AVIF عبر plugin أقل مباشرة |
| ImageMagick CLI | مرن جدًا | أبطأ، استدعاء process، تحكم أقل برمجيًا |
| Squoosh/@jsquash (WASM) | يدعم AVIF في الواجهة | أبطأ وأثقل من native؛ مفيش داعي دلوقتي وإحنا على سيرفر |
| المتصفح (النسخة القديمة) | صفر تكلفة سيرفر، خصوصية | مُرمِّز محدود، مفيش AVIF موثوق → جودة/حجم أقل |

**الخلاصة:** `sharp` بيدّينا مُرمِّز AVIF native بأقصى `effort`، سريع، وبتحكم كامل
في الجودة/الأبعاد/الـ subsampling — أفضل توازن **حجم × جودة نص × بساطة**.

## 5) تقنية سلايدر before/after (من غير أي مكتبة)

نفس الفكرة زي قبل — CSS + JS خالص:

  `getBoundingClientRect`. الكود في `public/js/compressor.js`.

## 6) التشغيل والوصول الآمن (Deployment / Networking / Security)

### أ) التشغيل
`npm start` (في cmd) مع ضبط كلمة المرور:
```bat
set APP_PASSWORD=كلمة_مرور_قوية
npm start
```
السيرفر افتراضيًا بيربط على **`127.0.0.1:8080` (loopback)** — يعني **مش مكشوف على
الشبكة ولا النت مباشرةً**، بس الجهاز نفسه أو النفق بيوصله. لو عايز أجهزة الواي‑فاي
توصله مباشرة، `set HOST=0.0.0.0`.

### ب) الأمان (الأولوية) — إزاي محدش يوصل لباقي الجهاز
1. **عزل التطبيق:** السيرفر بيقدّم بس ملفات `public/` + endpoint واحد `/api/compress`.
   الرفع بيتخزّن **في الذاكرة** (`multer` memoryStorage) — **مفيش كتابة على الديسك**،
   ولا تصفّح ملفات، ولا أوامر نظام. حد أقصى للرفع 40MB.
2. **كلمة مرور (HTTP Basic Auth):** لما `APP_PASSWORD` متظبطة، **كل** request (صفحات
   + API) بيطلب اليوزر `admin` + الباسورد. من غير كده يرجّع 401. المقارنة بـ
   `crypto.timingSafeEqual` (مقاومة timing attacks).
3. **ربط loopback:** الافتراضي `127.0.0.1` → التطبيق مش متسمّع على الشبكة إلا لو
   اخترت بنفسك `HOST=0.0.0.0`.

### ج) الوصول من بره البيت — Cloudflare Tunnel (الطريقة الآمنة)
بدل ما نفتح منفذ على الراوتر (اللي بيكشف الجهاز للنت)، بنستخدم **نفق**:
```bat
cloudflared tunnel --url http://localhost:8080
```
- النفق بيعمل اتصال **صادر (outbound)** من الكمبيوتر لـ Cloudflare → **مفيش أي منفذ
  داخلي بيتفتح** على الراوتر أو الفايروول. يعني باقي الجهاز والشبكة **مش مكشوفين**؛
  الوصول بيوصل بس لـ `localhost:8080` (التطبيق ده لوحده) وعبر النفق.
- بيدّي URL **HTTPS** عام (`https://xxxx.trycloudflare.com`). مع `APP_PASSWORD`،
  اللي معاهوش الباسورد ميقدرش يستخدمه.
- الـ quick tunnel بيتغيّر URL كل مرة. لـ URL ثابت + أقوى حماية (Cloudflare Access /
  تسجيل دخول Google) → **named tunnel** بحساب Cloudflare مجاني + دومين.
- بدائل بنفس أمان "صفر منافذ مفتوحة": **Tailscale** (خاص، أجهزتك بس) أو **ngrok**.

**ليه مش port-forwarding؟** لأنه بيفتح ثغرة داخلية النت كله يقدر يفحصها، و IP البيت
بيتغير. النفق بيتجنّب ده كله.

### د) ملاحظة نشر
التطبيق بقى server-side فمينفعش يشتغل على **GitHub Pages** (استضافة static بس).
الـ workflow القديم للـ Pages اتشال.

## 7) الإمكانيات (الروافع اللي نقدر نوسّعها بسهولة)

كلها في `server.js` في مكان واحد واضح:
- **الجودة (`AVIF_QUALITY`)** — نوازن وضوح × حجم لكل نوع محتوى.
- **الأبعاد (`MAX_DIMENSION`)** — أقوى رافعة توفير.
- **الصيغة** — AVIF دلوقتي؛ نقدر نضيف WebP/JPEG fallback لو احتجنا توافق أوسع.
- **Presets** — مستويات (أعلى جودة / متوازن / أصغر حجم) يختارها المستخدم.
- **Batch** — ضغط أكتر من صورة في request واحد.
- **الاحتفاظ بالأصل** أو استبداله، وتخزين نسخ (thumbnail/preview/original).
- **PDF** — libvips يقدر يقرا صفحات PDF، فممكن نمد الأداة للمستندات PDF.

**الخلاصة التقنية:** عندنا pipeline ضغط server-side كامل بـ `sharp`/AVIF، مضبوط
للمستندات (نص واضح + أصغر حجم)، ثابت على أي جهاز، وقابل للتوسّع بأقل مجهود لأن كل
المنطق متركّز في `server.js`.
